# grind-pda Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add CPU-only `grind-pda` and `verify-pda` subcommands that mine a seed such that `find_program_address(seeds, program_id)` matches the existing `--pattern` syntax, at SHA-256-midstate speed.

**Architecture:** New `src/pda.rs` module holds seed-spec parsing, the PDA message layout (midstate + spliceable tail template), and the per-thread odometer that steps the 16 alnum ground bytes. `src/main.rs` gains the two subcommands, reusing the existing plumbing (`resolve_spec`, `live_targets`, `credit_kinds`, UI reporter, rayon loop) and the existing digest-level matcher `fast::MatchTargets::match_mask_active` (which already does prefix byte-range rejection + limb-level base58 early-exit on raw 32-byte digests — no new range filter needed). Off-curve check runs only on pattern hits, via `Pubkey::create_program_address` (bump 255); a hit is credited only after it passes.

**Tech Stack:** Rust; `sha2::compress256` for the hot loop; `solana-pubkey` with the `curve25519` feature for off-curve checks and `verify-pda`.

**Spec:** the task brief pasted in conversation (PDA grind, bump-255-only policy, KAT vectors with program `T1TANpTeScyeqVzzgNViGDNrkQ6qHz9KrSBS4aNXvGT`).

## Global Constraints

- PDA preimage: `seed_0 ‖ … ‖ seed_n ‖ [bump] ‖ program_id(32) ‖ b"ProgramDerivedAddress"`; bump policy: hash with 255 only; discard on-curve hits; never search other bumps.
- Limits: grind_prefix.len() + 16 ≤ 32; total seeds incl. ground ≤ 15 (bump is the 16th); each fixed seed ≤ 32 bytes.
- SPEC formats: `str:<utf8>`, `hex:<bytes>`, `pubkey:<base58>`, `u64le:<n>`, `u8:<n>`.
- Ground seed = grind_prefix ‖ 16 chars from the 62-char alnum alphabet used by `grind`.
- Expected attempts shown in UI = bs58 expectation × 2 (off-curve halving).
- `grind`, `grind-keypair`, `grind-doppler`, `verify`, `deploy` unchanged; `--features gpu|opencl|metal` still compile; kernels/ untouched. GPU builds of `grind-pda` ignore `--num-gpus` with a message.
- rustfmt max_width 72; clippy `-D warnings` with the `[lints.clippy]` allows; CI = `cargo test --locked` (+deploy), clippy for default/deploy/opencl/gpu.

## Review Focus

1. `hex:` with odd length or non-hex chars → clear error (not a slice panic). Test in Task 1.
2. `--grind-index` greater than the number of fixed seeds → clear error naming the valid range. Test in Task 1.
3. `--grind-prefix` longer than 16 bytes (prefix+16 > 32) → clear error. Test in Task 1.
4. Patterns starting with '1' (no range filter; leading-zero digests) must still match PDA digests correctly. Covered by Task 4 agreement test.
5. An on-curve bump-255 hit must not consume quota or print — otherwise `--count N` stops early with fewer results. Covered by KAT-on-curve test (Task 4) + loop ordering (credit after pass) in Task 5.

### Task 2: PDA midstate template

**Interfaces (produces):**
- `pub struct PdaLayout` built by `PdaLayout::new(fixed: &[SeedSpec], grind_prefix: &str, ground_index: usize, program_id: &Pubkey)`
- `pub struct PdaTemplate` (per-thread clone): `fn splice(&mut self, ground16: &[u8; 16])`, `fn digest(&self) -> [u8; 32]`
- `PdaLayout::seeds_with_ground(&self, ground16) -> Vec<Vec<u8>>` (full seed list incl. grind_prefix‖ground, for `create_program_address` / printing)

Message = fixed seeds with `grind_prefix ‖ [0;16]` placeholder inserted at ground_index, then `[255]`, program_id, `b"ProgramDerivedAddress"`. Midstate = `sha2::compress256` from the SHA-256 IV over all whole 64-byte blocks before the ground-16 offset; tail = rest + SHA padding, splice offset recorded.

Tests (failing first): template digest == `Sha256::digest(full message)` for layouts: ground only; ground first/middle/last among fixed seeds (`pubkey:` + `u64le:` fixed seeds); with/without grind_prefix; a prefix long enough to push the ground bytes across the 64-byte block boundary. Then implement, test, commit.

### Task 3: Odometer ground-seed stepper

**Interfaces (produces):**
- `pub struct Odometer` — `fn random() -> Self`, `fn write(&self, out: &mut [u8; 16])` (alnum bytes), `fn step(&mut self)` (base-62 odometer, random start per thread)

Tests: bytes always in the 62-char alphabet; `step` changes exactly the expected positions (carry walk); two `random()` instances differ; stepping 62 times carries. Implement, test, commit.

### Task 5: CLI wiring

**Files:** Modify `src/main.rs`: `Command::GrindPda(GrindPdaArgs)`, `Command::VerifyPda(VerifyPdaArgs)`; `fn grind_pda`, `fn verify_pda`; `VanitySpec::live_targets_scaled(count, max_count, prob_factor)` (existing `live_targets` delegates with 1.0; grind-pda passes 0.5).

- `GrindPdaArgs`: `--program-id`, repeatable `--seed <SeedSpec>`, `--grind-prefix` (default ""), `--grind-index`, flattened `PatternArgs`, `--num-cpus`, `--count`, `--max-count`, and under `cfg(feature="gpu")` a `--num-gpus` that prints "grind-pda is CPU-only; ignoring --num-gpus" when nonzero.
- Loop per rayon thread: clone template, `Odometer::random()`; per attempt: write+splice, `digest()`, batch `TOTAL_ATTEMPTS` by 4096, `match_mask_active(&digest, unfilled_mask(max_count))`; on nonzero → `create_program_address(seeds+[255])`; accept only when `Ok(pda)` and `pda.to_bytes() == digest`, then `credit_kinds`, then `ui_with_match` printing PDA, bump 255, every seed (readable + hex), and a paste-ready `create_program_address(&[b"…", &[255]], &ID)` snippet.
- `verify_pda`: `find_program_address`, print seeds (readable + hex), PDA, bump.

Build, run unit tests, commit.
